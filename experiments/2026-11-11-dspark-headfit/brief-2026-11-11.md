# 技術ブリーフ: DSpark投機デコードの受理率を上げるには（2026-11-11時点の実測）

あなたは投機デコード（speculative decoding）の専門家として招かれています。以下は**すべて実測値**です。この構成で「受理率（acceptance）と受理長（acceptance length）を劇的に上げる」ための助言をください。

## 1. 構成

- ハード: DGX Spark 4台（GB10 / 統合メモリ123GiB）、RoCE 4ノード ring（TP4）
- モデル: DeepSeek-V4.1-Flash-1017（MIT）。語彙 129,280、文脈長 1,048,576
- エンジン: vLLM 0.29.1rc1 のフォーク（ローカルパッチ650本、イメージ `spark-ds41f:1117-shard`）
- 投機: `method=dspark`（DSpark = 並列ドラフト＋逐次Markov補正）
  - `num_speculative_tokens=5`
  - `draft_tensor_parallel_size=4`
  - `draft_sample_method=greedy`, `rejection_sample_method=block`
  - `enable_adaptive_verification=true`, `adaptive_verification_row_cost=0.035`
- KV: `--kv-cache-memory-bytes 11274289152`（1ランク10.5GiB）、`--max-num-seqs 16`、`--block-size 256`、`--max-num-batched-tokens 16384`、`--enable-chunked-prefill`、`--prefill-yield short`（10s）
- 生成既定: temperature 1.0 / top_p 1.0

## 2. ドラフターの実体（チェックポイントを読んで確認済み）

- ドラフターはチェックポイントの **MTPスタック**（`num_nextn_predict_layers=3`、`mtp.0/1/2`）。実体は `mtp.2` が持つ
- `mtp.2.markov_head.embed.weight` **[129280, 256] BF16**（W1）、`mtp.2.markov_head.head.weight` **[129280, 256] BF16**（W2）
- `mtp.2.confidence_head.proj.weight` **[1, 5376] BF16**
- バイアスは `bias = W2 @ W1[prev_token]` をドラフターのlogitsに加算。**文脈非依存（直前トークンのみ）**
- `mtp.*` の総要素数 7.86B（ffn 7.33B / attn 380M）、`mtp.0.ffn` は128エキスパート×6テンソル（top-3）
- 量子化は混合精度（experts FP4、markov/confidence headはBF16のまま）

- 実機A/B: 受理率 +0.3pt / 受理長 +0.04（**誤差の範囲**、run間の揺れ 0.635–0.642）

## 4. 構造上わかっている制約（ここを踏むと起動しない/落ちる）

1. TP4では語彙が4分割され、本番のgreedy経路は**shard局所の (max,idx) ペア還元**で、全語彙logitsを作らない
2. 密経路（`vocab_parallel=False`）に倒すと `markov_bias` の全語彙前提が壊れ **CUDA不正アクセス**
3. **カーネルキャッシュは温め後に凍結**。起動後に経路を変えると `KernelNotPreparedError`
4. `--enforce-eager` 中は adaptive verification 不可（pydantic validation で排他）
5. CUDA graph キャプチャ中のホストコピーは禁止（`_sample_sequential` はグラフに入る局面がある）→ 採取は `--enforce-eager` で行う
6. トレースはrank0のみ・`/cache` へ書く。非対称にすると集合通信がデッドロック

## 5. 使える計測基盤（すでにある）

- 実プロンプトのリプレイ: `~/scripts/dspark/capture_replay.py --n 100 --temperature 0 --concurrency 4`（受理率・受理長・tok/sを出力）
- 再起動を伴うA/B: `markov_sweep.sh`（`MARKOV_SCALE` 掃引）
- トレース採取: マーカー `ENABLED` / `TOPK=64` / `SHARDTOPK=32` / `HIDDEN=0` を4ノードの `cache/dspark-trace/` に置き、`--enforce-eager` で起動 → `trace.jsonl` に `l`（ターゲットtop-64）と `dl`（ドラフターのバイアス前top-32）が出る
- 重みの配備: チェックポイント・オーバーレイ（`build_markov_overlay.py`、markovの2テンソルだけ差し替え、再ビルド不要・1行でロールバック）
- 受理率の内訳は実運用ログからも取れる（`vllm-spec-proxy` が `summary-YYYY-MM-DD.md` を毎朝出力）
